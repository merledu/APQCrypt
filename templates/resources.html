System condition and policy

Live CPU and memory readings, and the decision table that maps sensitivity and system condition to an algorithm.

How the policy is chosen

Before encrypting, the policy engine averages a short series of CPU readings and reads memory use. If either is at or above its limit, the system is Constrained; otherwise it is Available. A constrained system gets cheaper algorithms.

HIGH sensitivity flows always keep the hybrid quantum-safe key exchange. Only the bulk cipher and the MEDIUM key exchange adapt to load. Every cipher is authenticated (AES-GCM or ChaCha20-Poly1305), so tampering is detected.

The CPU and memory limits are design parameters and should be calibrated on the target RISC-V board.
